# 本地网站使用说明

本地地址：**http://127.0.0.1:5173/**。直接访问学校账号登录页，不经过ChatGPT、Sites登录、微信或外部身份认证。

## 首次配置账号

账号密码不随源码上传。新电脑或服务器首次运行前：

1. 创建 `.local-study/` 目录，把 `local/initial-accounts.example.json` 复制为 `.local-study/initial-accounts.json`。
2. 在复制的文件中填写账号名称和密码。密码为空时拒绝初始化。
3. `shortcutUsername` 指定账号留空时使用的账号，仍须正确输入该账号的当前密码。设为空字符串可停用此快捷登录。
4. 初始账号设置仅在首次启动写入数据库；已有账号、密码、10个座位及预约记录不会因更新代码而重置。

`mustChangePassword` 表示首次登录是否必须改密。原开发电脑已有账号保持不变，继续使用此前设置的密码。学校真实账号仍待学校数据库接入。

## 启动与停止

已安装依赖并构建后，双击项目中的 `启动网站.command`；或在项目根目录执行：

```sh
npm run local
```

双击启动文件会自动打开浏览器；若网站已经运行，则直接打开现有网站，不会重复启动。首次启动后保持终端窗口运行，按Ctrl+C停止。只监听本机127.0.0.1，其他设备不能通过这个地址访问。默认端口5173，被其他程序占用时会提示错误，不会终止其他服务。

修改网页后重新构建再启动：

```sh
npm run build:local
npm run local
```

首次在另一台电脑使用，需先安装Node.js22.13以上并执行 `npm --prefix website run install:ci`，再构建。构建产物在 `website/local-dist/`，运行时仅需Node.js，无需云开发环境和联网登录。

## 数据保存

登录后，页面顶部的黄色“问题反馈”按钮可提交1～5星使用体验评分，以及选填的问题描述（最多1000字）。反馈与账号关联，提交成功后保存在本机后台。

管理员进入“管理工作台 → 用户反馈”，可按时间从新到旧查看评分、留言、账号和提交时间，并加载更多记录。学生和审核员无权读取反馈列表。演示模式不提交反馈。

- `.local-study/initial-accounts.json`：本机初始化账号配置，包含密码，不得提交到代码仓库。
- `.local-study/records.json`：本地账号密码摘要、预约、额度、处罚、审核、用户反馈与会话等。
- `.local-study/photos/`：上传的举报照片，只有授权用户经短期链接查看。
- `.local-study/owner.lock`：单进程运行锁，正常退出自动移除。

数据目录已被Git忽略。备份时先停止网站，再复制整个 `.local-study/`。不要删除该目录，删除会丢失测试数据。服务采用串行事务与原子文件替换，同座位竞争只有一人成功；写入失败不提交内存状态。遇到损坏的数据文件会拒绝启动，不自动覆盖。

本地版沿用原有预约、角色、举报和处罚规则，但使用独立文件存储，不连接学校数据库或以前的云端站点。实际学校数据接入需等学校提供账号验证方式。

## 开发与校验

- `npm test`：业务、认证、本地持久化、并发、照片授权和迁移测试。
- `npm run check`：当前JavaScript和JSON静态检查。
- `cd website && npx tsc --noEmit`：网页类型检查。
- 当前入口为 `website/local/main.tsx`，本地API为 `local/app.js`，服务为 `local/server.js`。
- `cloudfunctions/study/application.js` 提供共享业务接口，`index.js` 仅保留旧云端部署适配。

旧Sites托管配置和网站历史仍保留，但本地构建不加载其登录或连接器模块。按用户要求，后续默认本地运行，不发布到Sites。微信功能继续保存在原归档目录。
