# 网站部署与账号登录

当前只提供网站，源码在 `website/`，后台在 `cloudfunctions/study/`。学生用学校已有账号和原密码登录；工作人员用管理员发放的账号密码登录。学校数据源与实际后台环境尚未配置，站点现在提供明确标注的浏览器本地演示。

## 服务端配置

1. 按根README配置云数据库、私有证据存储及云函数，将 `study` 暴露为HTTPS入口。HTTP事件需包含 `httpMethod`、`headers`、原始 `body` 和可选 `isBase64Encoded`。实际入口形式须在所用平台联调确认。
2. 生成至少32字符高熵共享密钥，云函数与网站服务端分别保存，绝不放入客户端、Git或聊天消息。
3. 云函数变量：`WEB_GATEWAY_SECRET`（共享密钥）、`WEB_SITE_ORIGIN`（网站准确origin，不带末尾斜杠，例如 `https://study-commons-committee.mmasondu.chatgpt.site`）。
4. 网站服务端运行时变量：`STUDY_API_URL`（HTTPS云函数入口）、`STUDY_GATEWAY_SECRET`（同一个共享密钥）。在Sites托管运行时配置，本地可使用被Git忽略的 `.dev.vars`；不使用 `NEXT_PUBLIC_` 前缀。
5. 云函数设置初始管理员变量 `INITIAL_ADMIN_USERNAME`、`INITIAL_ADMIN_PASSWORD`，通过网站账号密码入口首次创建管理员。账号3～32位字母、数字、下划线或短横线，初始密码10～100位且包含字母和数字。首次登录须修改密码，完成后移除这两个环境变量。
6. 学校原账号接入后再邀请师生使用。当前站点仅所有者可访问，后续须按学校要求配置访问范围。

不再需要小程序AppID、微信绑定、二维码或 `WECHAT_CODE_VERSION`。云函数保留数据库及存储SDK用途，开放接口权限列表为空。非HTTP的小程序调用直接拒绝，扫码、绑定和解绑动作均不在允许列表。

## 会话与数据

- HTTPS请求使用完整请求体HMAC、时间窗口和一次性nonce校验，浏览器请求也校验Origin及业务动作白名单。
- Cookie使用HttpOnly、SameSite=Strict，HTTPS使用Secure。当前只接受通过密码验证签发的新网页会话，迁移前所有旧会话失效，历史预约、额度和处罚仍保留。
- 登录按浏览器和账号限流，每15分钟20次。实际环境应另配适当的HTTP请求速率限制。
- `webNonces`及过期会话包含毫秒数字 `expiresAt`，可按类型和时间运维清理；nonce至少两分钟后清理。历史 `webLogins`、`wechatBindings` 记录不被主动使用，此次不执行数据删除。
- 网站可见时每20秒刷新数据，支持手动刷新。未连接时的40席、演示学生及预约均为浏览器本地示例。

## 本地检查

Node.js22.13以上，首次 `cd website && npm run install:ci`，随后 `npm run dev -- --hostname 127.0.0.1`。根目录 `npm test && npm run check` 检查后台；网站 `npx tsc --noEmit` 检查类型。归档目录不参与构建。

## 实际环境验收

- 网站可直接初始化管理员、强制修改初始密码，并发放审核账号。
- 已存在学校账号可直接密码登录，不受历史微信绑定影响；未知账号、停用账号和错误密码均失败。
- 旧扫码/小程序会话和所有退休入口被拒绝；旧网站会话也须重新输入账号密码。
- 两浏览器并发预订同座同时间，只有一个成功；取消仅返还一次额度，封禁后两浏览器均无法预约。
- 举报照片必须属于提交人，普通学生不可访问他人证据；审核权限由服务端执行。
- 密码重置、角色变化和学校停用后旧会话失效；原有额度、预约和处罚保持连续。

SDK替身测试只验证本地接口契约，不能代替HTTP入口和云数据库事务的线上验收。
